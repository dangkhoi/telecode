Spec · Telecode v1.2

Telegram media input + verbose-button fix

Người dùng gửi hình + file vào chat Telegram, telecode lưu local rồi inject reference cho agent đọc bằng Read tool. Đồng thời gỡ noise: button "Tiếp tục" / "Re-run" gắn dưới mỗi tool result khi agent đang chạy.

Slug · telegram-media-input Author · vendor.01@frt.vn Date · 2026-05-21 Effort · ~1 đêm (autonomous) Status · Implementing

TL;DR

(1) Verbose-button noise: suggestion row [▶️ Tiếp tục] [🔁 Run again] hiện được attach lên TỪNG tool_result. User nhìn thấy nó dưới mỗi message khi agent đang chạy → confusing + noise. Fix: chỉ attach 1 row duy nhất lên message CUỐI của turn (sau done event), không attach mid-stream.

(2) Image + file input: thêm bot.on('message:photo' | 'message:document', ...). Download file qua Bot API → save vào ~/.telecode/inbox/<chatId>/<yyyymmdd-HHMMSS>-<name> → inject reference @<abs-path> vào prompt cho agent. Unified per-agent (Claude / Kiro / Codex / Cursor đều dùng Read tool).

Trade-off: KHÔNG dùng Claude SDK base64 content-block (sẽ ép phải refactor sang streaming-mode prompt — disruptive cho session resume + abort). @path approach uniform cho 4 adapter, ít diff hơn, dễ test, đồng nhất UX.

Context

3 yêu cầu user đêm 21/05 sau hotfix 4-bug.

Yêu cầu nguyên văn

  1. Chọn mode verbose, dưới mỗi message luôn có button "Tiếp tục", đôi khi thêm button "Re-run", chưa hiểu để làm gì khi agent đang chạy? Có dư thừa không, kiểm tra và fix.
  2. Thêm function gửi hình ảnh, screenshot, các agent cli đều có /paste (Kiro) hay cách nào đó để user input hình ảnh, hãy làm feature này, khi user gửi hình vào telegram thì hãy lấy hình đó gửi cho agent theo đúng cú pháp từng agent.
  3. Thêm function send được file, các file format căn bản như md, html, word, excel … để làm đầu vào cho các promt khi user cần.

Hiện trạng codebase

  • src/bot/suggestions.ts · buildSuggestions() hard-code mỗi tool_result đều có ít nhất 1 button "▶️ Tiếp tục" + đôi khi "🔁 Run again" / "↩️ Rollback".
  • src/bot/commands/index.ts · attach row vào mọi tool_result trong nhánh e.type === 'tool_result' (~L1521–L1605) + retrofit khi defer timeout (~L1186–L1205).
  • bot.on('message:text', ...) tồn tại — KHÔNG có handler cho :photo / :document. Photo / file gửi vào hiện bị silent-drop.
  • 4 adapter (claude.ts, kiro.ts, codex.ts, cursor.ts) đều nhận initialPrompt: string qua AgentStartOpts. Claude SDK technically support multimodal qua streaming-mode async iterator, nhưng telecode dùng string-prompt mode.

Requirements

Acceptance criteria — verified trong consolidate phase.

R1 — Suggestion buttons không noise khi đang chạy

  • R1.1 · Trong khi turn đang chạy (chưa nhận done / error), KHÔNG attach suggestion row vào bất kỳ tool_result message nào.
  • R1.2 · Sau khi nhận done, attach ĐÚNG 1 suggestion row vào done summary card (cuối turn). Không attach vào event nào khác.
  • R1.3 · Nếu turn error ra giữa chừng → vẫn attach 1 row vào error message (để user dễ Tiếp tục / Re-run).
  • R1.4 · Defer-timeout retrofit (cho adapter không emit tool_result) cũng DROP — không retrofit suggestion mid-stream.
  • R1.5 · Diff button [📜 Show diff] + AI summary button [💬 AI summary] được PRESERVE per-tool (đây không phải suggestion, là affordance cho riêng tool đó — đúng moment).

R2 — Image input từ Telegram

  • R2.1 · Khi user gửi photo vào chat đang có active session, telecode download largest-resolution variant về local.
  • R2.2 · Photo lưu tại ~/.telecode/inbox/<chatId>/<yyyymmdd-HHMMSS>-<rand6>.<ext>. ext infer từ MIME hoặc default .jpg.
  • R2.3 · Reject quá size cap (default 20 MB — match Telegram bot API limit).
  • R2.4 · Caption (nếu có) trở thành body của prompt. Prompt cuối cùng append dòng 📎 Attached image: @<abs-path> để agent thấy reference.
  • R2.5 · Nếu không có caption → prompt mặc định "Xem ảnh đính kèm và cho biết bạn thấy gì." + @path.
  • R2.6 · Không có active session → reply hướng dẫn (giống message:text).

R3 — File input từ Telegram

  • R3.1 · Khi user gửi document vào chat đang có active session, telecode download về local.
  • R3.2 · File lưu tại ~/.telecode/inbox/<chatId>/<yyyymmdd-HHMMSS>-<original-filename>. Filename sanitize: bỏ path separators, control chars, max 80 chars stem.
  • R3.3 · Extension allowlist: .md .markdown .html .htm .txt .csv .tsv .json .yaml .yml .xml .log .docx .doc .xlsx .xls .pptx .ppt .pdf .rtf .ts .js .py .go .rs .java .sh .sql .toml .ini. File ngoài allowlist → reject với hint.
  • R3.4 · Size cap default 20 MB. Configurable qua config.telegram.attachmentMaxBytes.
  • R3.5 · Caption (nếu có) trở thành body prompt. Default nếu trống: "Đọc file đính kèm rồi trả lời tiếp.".
  • R3.6 · Prompt append 📎 Attached file: @<abs-path> (<size>, <ext>) để agent biết đường dẫn + metadata.

R4 — Cross-adapter compatibility

  • R4.1 · 4 adapter (claude, kiro, codex, cursor) đều nhận prompt string không thay đổi. Image/file injection xảy ra ở layer bot/commands, KHÔNG đụng agents/*.
  • R4.2 · Path inject là absolute, agent Read tool gọi được trực tiếp. Quote không bắt buộc — assume @path convention.

Design

Architecture + key decisions + file plan.

D1 — Suggestion-button defer (Bug 1)

Trước

tool_result event → resolve pending → buildSuggestions → attach row vào EVERY tool_result message
defer timeout 2s → retrofit suggestion row nếu tool_result không tới

Sau

tool_result event → resolve pending → attach CHỈ diff/summary button (per-tool affordance)
done event → attach 1 suggestion row vào done-summary card (1 lần / turn)
error event → attach 1 suggestion row vào error message (1 lần / turn)
defer timeout → KHÔNG retrofit suggestion (giữ retrofit diff button nếu có)

Logic: suggestion row tập trung vào "what should I do NEXT" — chỉ có nghĩa khi turn done. Trong khi đang chạy, agent vẫn sẽ tự tiếp tục → button "Tiếp tục" / "Run again" gây hiểu nhầm.

D2 — Attachment download path

// src/bot/attachments.ts (new module)
export interface SavedAttachment {
  absPath: string;        // ~/.telecode/inbox/<chat>/<ts>-<name>
  filename: string;       // sanitized
  sizeBytes: number;
  kind: 'photo' | 'document';
  ext: string;            // ".png" / ".docx" / ...
}

export async function downloadTelegramFile(
  bot: Bot,
  chatId: number,
  fileId: string,
  hintName: string | null,   // null cho photo → infer từ mime
  opts: { maxBytes: number; allowedExts?: Set<string> },
): Promise<SavedAttachment | { error: string }>;

Implementation:

  1. bot.api.getFile(fileId) → { file_path, file_size }
  2. Check file_size > maxBytes → return error.
  3. Compose URL https://api.telegram.org/file/bot<token>/<file_path>.
  4. fetch(url) → stream vào file local. (Node 22 native fetch.)
  5. Filename sanitize: replace [^\w.\-] → _, truncate stem ≤ 80 chars, preserve ext.
  6. Cross-platform: os.homedir() + path.join + fs.mkdir(recursive: true). Windows OK.

D3 — Handler wiring

// src/bot/commands/index.ts (new bot.on handlers, placed AFTER message:text)

bot.on('message:photo', async (ctx) => {
  const photos = ctx.message.photo;          // PhotoSize[]
  const largest = photos[photos.length - 1]; // last = highest res
  const result = await downloadTelegramFile(
    bot, ctx.chat!.id, largest.file_id, null,
    { maxBytes: cfg.telegram.attachmentMaxBytes },
  );
  if ('error' in result) { await ctx.reply(result.error); return; }
  await routeAttachmentToActiveSession(ctx, result, ctx.message.caption);
});

bot.on('message:document', async (ctx) => {
  const doc = ctx.message.document;
  const result = await downloadTelegramFile(
    bot, ctx.chat!.id, doc.file_id, doc.file_name,
    { maxBytes: cfg.telegram.attachmentMaxBytes, allowedExts: FILE_ALLOWLIST },
  );
  if ('error' in result) { await ctx.reply(result.error); return; }
  await routeAttachmentToActiveSession(ctx, result, ctx.message.caption);
});

routeAttachmentToActiveSession() tái sử dụng dispatch path của bot.on('message:text'):

function buildPromptWithAttachment(caption, att): string {
  const body = caption?.trim() || (att.kind === 'photo'
    ? 'Xem ảnh đính kèm và cho biết bạn thấy gì.'
    : 'Đọc file đính kèm rồi trả lời tiếp.');
  const sizeHint = formatBytesShort(att.sizeBytes);
  const meta = att.kind === 'photo'
    ? `📎 Attached image: @${att.absPath} (${sizeHint})`
    : `📎 Attached file: @${att.absPath} (${sizeHint}, ${att.ext})`;
  return `${body}\n\n${meta}`;
}

Findings & Fixes

  • [P2] attachments.ts · mkdirSync trong ensureInboxDir không có try/catch → EACCES/ENOTDIR/EPERM trên home read-only sẽ crash bot.on handler trước khi reply error. Fixed: wrap try/catch, return { error } result; downloadTelegramAttachment short-circuits với friendly Vietnamese message. Test: attachments.test.ts · "returns friendly error when inbox dir cannot be created".
  • [P2] attachments.ts · photo extension luôn hard-code .jpg bất chấp content thật (Telegram nén PNG/WebP) — agents key off ext sẽ mis-handle. Fixed: infer ext từ meta.file_path với regex /^\.[a-z0-9]{1,5}$/ guard, fallback .jpg. Tests: 2 new (PNG inference + fallback path).
  • [P2] commands/index.ts · photo/document error replies dùng ctx.reply(result.error) trực tiếp, bypass Notifier.scrubSecrets. Network error message từ fetch clean by default, nhưng adversarial server có thể echo URL chứa bot token. Fixed: wrap scrubSecrets(result.error) trước khi reply (defense-in-depth).
  • [P3] commands/index.ts · (bot as unknown as { token: string }).token cast không cần — grammy 1.43 Bot.d.ts §106 declare readonly token: string public. Fixed: bỏ cast, dùng bot.token trực tiếp với comment giải thích.

Items Reviewed and Approved (no patch)

  • Path traversal — sanitizeFilename regex strips /, \, :, control chars; ../etc → .._etc (single segment). path.join(dir, finalName) can't escape inboxRoot.
  • Stream backpressure — Readable.fromWeb() + pipeline() handles backpressure; the 'data' listener we add is observer-only (doesn't consume), so pipeline still drains via pipe() internal plumbing. No data loss.
  • Partial-write recovery — pipeline rejects → unlink partial file in best-effort manner; try{}catch{} on unlink prevents secondary leak.
  • Concurrent download race — mkdirSync({recursive:true}) idempotent + atomic; randomBytes(3) = 16M permutations, prefix collision odds << than the second-resolution timestamp collision odds (which itself is fine).
  • Cross-platform — path.join, os.homedir(), no hard-coded separators. Filename sanitize strips Windows-forbidden chars (: * ? " < > |) by the same allowlist regex.
  • Token redaction — Notifier.scrubSecrets covers TG token regex (verified at src/util/scrub.ts:9). Photo/document handler replies now also pass through it.
  • Claude SDK done-dedup — confirmed against Context7 SDKResultMessage schema; type:'result' + onResultDone() wiring covers both success + error subtypes uniformly.
  • Suggestion-row gating — verified through tests/end-of-turn-suggestions.test.ts + dispatch path traces (lines 1599, 1767, 1845): no mid-stream attach point remaining.
