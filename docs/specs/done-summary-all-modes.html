Done-summary đầy đủ cho mọi verbosity mode

Đảm bảo sau khi hoàn tất MỖI tác vụ, ở BẤT KỲ verbosity mode nào (summary / normal / thinking / verbose), người dùng luôn nhận được một bản tóm tắt đầy đủ thông tin để nắm kết quả — không bao giờ rơi vào tình trạng "bot trả lời nhưng màn hình trống".

Slug · done-summary-all-modes Author · vendor.01@frt.vn Date · 2026-05-22 Effort · ~0.5 ngày Status · Implemented · senior-reviewed · pending daemon reload

TL;DR

Triệu chứng user gặp: hỏi câu dài → màn hình Telegram "không có content". Root cause: session ở verbosity mode summary (do default DEFAULT_VERBOSITY_MODE='summary', session mode=null) → shouldEmit('text')=false → toàn bộ streaming text bị chặn; user chỉ còn trông cậy vào auto-done-summary, vốn (a) chỉ chạy ở summary/normal, (b) bị nuôi bằng transcript_tail chỉ-dòng-cuối, (c) instruction ép "1-2 câu, không giải thích" → quá cụt.

Yêu cầu user (nguyên văn): "ở bất cứ mode nào, cũng cần phải summary đầy đủ thông tin cho người dùng đọc, ngay cả mode verbose, khi làm xong 1 tác vụ, cũng cần summary lại, đảm bảo đủ content để user nắm."

Fix (4 điểm): (1) bật auto-done-summary ở cả 4 mode; (2) nuôi summarizer bằng full turn text tích lũy trong turn thay vì transcript_tail; (3) viết lại instruction để summary đầy đủ, tự-chứa; (4) guaranteed-content fallback — khi summarizer fail/timeout thì gửi thẳng full text (chunked) để content không bao giờ mất. Bonus: đổi DEFAULT_VERBOSITY_MODE → 'normal'.

Vì sao "tin đầu có vẻ tới, tin sau trống"

Thực chất user chưa bao giờ thấy nội dung streaming thật ở mode summary — chỉ thấy done-summary. Tin mô tả ảnh thì summary đủ nghĩa nên tưởng OK; các bài phân tích dài thì summary 1-2 câu không tải nổi nội dung → cảm giác "trống". Đây là class bug "content loss", không phải "render/markdown/chunk" như giả thuyết ban đầu.

Design Approval gate #2

Sẽ hoàn thiện chi tiết song song khi implement (DAG). Bản nháp định hướng dưới đây.

D1 — Bật done-summary mọi mode (R1)

commands/index.ts:1842: bỏ điều kiện (currentMode==='summary' || currentMode==='normal'). enableAutoDoneSummary chỉ còn phụ thuộc !approvalInFlight && hasResumeId && hasContent. Mode verbose/thinking trước đây rơi vào nhánh baseline-tail giờ cũng nhận done-summary recap.

D2 — Full turn text thay vì transcript_tail (R2)

Trong onEvent của dispatch chính, tích lũy một biến turnText (đóng theo scope mỗi turn) cộng dồn mọi e.text (không chỉ dòng cuối). Khi done, dùng turnText.trim() làm input summarize (fallback transcript_tail rồi doneResultText nếu rỗng). Không đụng cơ chế transcript_tail hiện có (vẫn dùng cho /sessions preview).

Lưu ý bộ nhớ: cap turnText ở ngưỡng an toàn (ví dụ 32KB) để tránh phình RAM với turn cực dài; vượt thì giữ phần đầu + phần cuối.

D3 — Instruction giàu nội dung (R2)

Viết lại AUTO_DONE_SUMMARIZE_INSTRUCTION: yêu cầu bản tóm tắt tự-chứa, đủ để người đọc nắm kết quả mà không cần xem chi tiết; giữ con số/kết luận/đường dẫn quan trọng; cho phép gạch đầu dòng; độ dài thích ứng (ngắn cho việc nhỏ, có cấu trúc cho việc lớn). Bỏ ràng buộc "1-2 câu / không giải thích".

D4 — Guaranteed-content fallback (R3, P0)

Khi summarizeWithSession trả null (timeout/crash):

  • Nếu text đã được stream trong turn (mode normal/thinking/verbose, turnText đã hiển thị) → giữ baseline tail ✅ Done là đủ (user đã thấy nội dung).
  • Nếu text bị suppress (mode summary) → gửi thẳng turnText qua sendChunked (đã có sẵn) để đảm bảo content tới user. Đây là điểm mấu chốt chống "màn hình trống".

Điều kiện rẽ nhánh dựa trên shouldEmit({type:'text'}, currentMode) — single source of truth, không hardcode lại tên mode.

D5 — Default mode normal (R4)

verbosity.ts:52: DEFAULT_VERBOSITY_MODE = 'normal'. Cập nhật doc-comment + test khẳng định default. Không migrate dữ liệu cũ (session mode=null tự hưởng default mới).
