1. Mục tiêu & Non-goals

Cái này làm để giải quyết gì, và quan trọng hơn — không làm cái gì.

Mục tiêu

  • Giảm gõ tay: 6 command thường dùng nhất chuyển từ "gõ slash + args" sang "tap nút".
  • Discoverable: user mới chỉ cần tap menu hoặc keyboard để khám phá command — không cần đọc README.
  • 0 rework cho T3: bake sẵn CallbackRouter, WizardState, ReplyBuilders. T3 (follow-up suggestions, one-tap allow, dashboard) sẽ là pure additive.
  • Persistent: reply keyboard luôn hiện (mode 2A) — quen tay như app native, không bật/tắt.
  • Resume: nếu daemon restart giữa lúc user đang trong wizard, conversation state phải restore được (qua SQLite-backed storage).

Non-goals (NOT làm trong sprint này)

  • ❌ Telegram Web App (Tier 4) — cần HTTPS public, vi phạm single-user / no-public-port principle.
  • ❌ One-tap "Allow always" trên approval message (Tier 3 #8) — defer.
  • ❌ Live status dashboard với editMessageText loop (Tier 3 #9) — defer.
  • ❌ Follow-up inline suggestions sau action (Tier 3 #7) — defer.
  • ❌ Localization (i18n) — single-user, single-language (vi).
  • ❌ Group chat support — vẫn single-user DM only.

2. Tech verification (Context7)

Đã verify qua Context7 trước khi viết plan. Tất cả API dùng đều là latest non-deprecated pattern.

Package Current Latest API dùng Status
grammy 1.43.0 1.43.0 setMyCommands, Keyboard, InlineKeyboard, setChatMenuButton, bot.callbackQuery() ✅ Latest
@grammyjs/runner 2.0.3 2.0.3 (no change) ✅ Latest
@grammyjs/conversations — 2.1.1 conversations(), createConversation(), conversation.form.select(), conversation.waitFor("callback_query:data") ➕ New dep

Decisions từ docs review

  • Skip @grammyjs/commands plugin: overkill cho single-user (chủ yếu giá trị ở localization + scoped admin commands). Dùng bot.api.setMyCommands([...]) built-in.
  • Conversations storage: dùng custom adapter trỏ vào ~/.telecode/state.db (đã có better-sqlite3). Schema thêm 1 bảng conversation_state(key TEXT PRIMARY KEY, data TEXT, updated_at INTEGER). Không thêm dep @grammyjs/storage-file hoặc redis.
  • Conversation version: bắt đầu version: 1. Tăng nếu sau này thay đổi logic wizard (sẽ wipe state cũ — chấp nhận được vì user phải restart wizard, không mất dữ liệu thực).
  • Callback data format: ns:action:payload — vd session:switch:abc123, wizard:new:agent:claude, project:cd:proj_42. CallbackRouter parse và dispatch theo ns:action, payload là phần còn lại. Giới hạn 64 bytes của Telegram callback_data — dùng project_id (uuid prefix 8 ký tự) thay vì full path.

3. Architecture & Shared infra

3 module mới phải build trong sprint này. T3 sau này reuse hoàn toàn — đây là chốt chặn không rework.

3.1 CallbackRouter (src/telegram/callback-router.ts)

Wrap bot.callbackQuery() thành dispatcher có namespace. Mỗi feature đăng ký handler qua router.on(ns, action, handler) thay vì if/else trên ctx.callbackQuery.data.

// src/telegram/callback-router.ts
export type CallbackHandler = (ctx: CallbackQueryContext<BotContext>, payload: string) => Promise<void>;

export class CallbackRouter {
  private handlers = new Map<string, CallbackHandler>();

  on(ns: string, action: string, handler: CallbackHandler): this {
    this.handlers.set(`${ns}:${action}`, handler);
    return this;
  }

  attach(bot: Bot<BotContext>): void {
    bot.on("callback_query:data", async (ctx) => {
      const data = ctx.callbackQuery.data;
      const [ns, action, ...rest] = data.split(":");
      const handler = this.handlers.get(`${ns}:${action}`);
      if (!handler) {
        logger.warn({ data }, "callback_router: no handler");
        await ctx.answerCallbackQuery();
        return;
      }
      try {
        await handler(ctx, rest.join(":"));
      } catch (err) {
        logger.error({ err, data }, "callback_router: handler failed");
        await ctx.answerCallbackQuery({ text: "⚠️ Lỗi xử lý, thử lại sau", show_alert: true });
      }
    });
  }
}

T3 reuse: router.on("approval", "allow-always", handler) cho one-tap allow. router.on("dashboard", "refresh", handler) cho dashboard.

3.2 WizardState (qua @grammyjs/conversations + SQLite adapter)

State machine multi-step được cung cấp bởi plugin @grammyjs/conversations. Ta wrap với SQLite storage adapter để persist qua restart.

// src/telegram/conversation-storage.ts
import type { StorageAdapter } from "@grammyjs/conversations";
import type { Database } from "better-sqlite3";

export function createSqliteConversationStorage(db: Database): StorageAdapter<unknown> {
  db.exec(`
    CREATE TABLE IF NOT EXISTS conversation_state (
      key TEXT PRIMARY KEY,
      data TEXT NOT NULL,
      updated_at INTEGER NOT NULL
    );
  `);
  const stmt = {
    read: db.prepare("SELECT data FROM conversation_state WHERE key = ?"),
    write: db.prepare("INSERT INTO conversation_state(key, data, updated_at) VALUES (?,?,?) ON CONFLICT(key) DO UPDATE SET data=excluded.data, updated_at=excluded.updated_at"),
    delete: db.prepare("DELETE FROM conversation_state WHERE key = ?"),
  };
  return {
    read: (key) => {
      const row = stmt.read.get(key) as { data: string } | undefined;
      return row ? JSON.parse(row.data) : undefined;
    },
    write: (key, data) => {
      stmt.write.run(key, JSON.stringify(data), Date.now());
    },
    delete: (key) => { stmt.delete.run(key); },
  };
}

T3 reuse: dashboard edit-flow, "rename session inline" v.v. có thể dùng conversation pattern tương tự, share cùng storage.

4.2 Persistent reply keyboard

6 nút luôn hiện dưới ô gõ. User tap = bot nhận message text tương ứng, parse như command bình thường.

// src/telegram/reply-builders.ts
export function buildPersistentKeyboard(): Keyboard {
  return new Keyboard()
    .text("📋 Sessions").text("📁 Projects").row()
    .text("📊 Status").text("🛑 Stop").row()
    .text("📸 Screen").text("❓ Help")
    .resized()
    .persistent();
}
┌─────────────────────────────┐ │ Bot reply nội dung ở đây... │ │ │ ├─────────────────────────────┤ │ [📋 Sessions] [📁 Projects] │ │ [📊 Status] [🛑 Stop] │ │ [📸 Screen] [❓ Help] │ ├─────────────────────────────┤ │ Type message... 🎤 ➤ │ └─────────────────────────────┘

Handler: bot match text "📋 Sessions" → dispatch /sessions logic. Map cố định trong src/telegram/keyboard-actions.ts.

Lưu ý: khi user vào wizard (multi-step input), keyboard tạm ẩn để tránh nhầm. Hoàn tất wizard → khôi phục.

5. Tier 2 — Wizards

Thay thế gõ args bằng tap nhiều bước. Build trên shared infra ở §3.

5.1 Wizard /new session (Agent → Project → Label)

1
Trigger

User gõ /new hoặc tap menu. Bot vào conversation newSession.

2
Choose agent

Bot reply inline keyboard:

Tạo session mới — chọn agent: [🤖 Claude] [⚡ Kiro] [✖ Cancel]

Callback data: wizard:new-agent:claude / wizard:new-agent:kiro / wizard:new-cancel.

3
Choose project

Sau khi tap agent, bot editMessageText show list project (đã register):

Agent: Claude ✓ Chọn project: [📁 telecode] [📁 api-service] [📁 mobile-app] [← Back] [✖ Cancel]

Callback: wizard:new-project:<project_id_short>. Phân trang nếu >10 projects (next/prev buttons).

4
Enter label

Bot editMessageText:

Agent: Claude, Project: telecode ✓ Nhập label cho session (vd: refactor-auth):

Conversation chờ conversation.form.text(). Validate: /^[a-zA-Z0-9_-]{1,40}$/. Sai → otherwise: "Label chỉ chứa chữ-số-_-, tối đa 40 ký tự".

5
Confirm + create

Bot tạo session qua SessionManager.create() (gọi qua conversation.external()), reply:

✓ Session [refactor-auth] tạo OK Agent: Claude · Project: telecode Gõ prompt để bắt đầu, hoặc: [🔀 Switch khác] [📋 Tail logs]

Edge cases: user gõ command khác giữa wizard → conversation tự exit (default behavior plugin), thông báo "Wizard đã hủy, thử lại bằng /new". Daemon restart → conversation state restore từ SQLite, user tiếp tục được.

5.2 Project picker (/projects + 📁 Projects button)

Tap 📁 Projects → bot reply inline keyboard list project. Mỗi project có 2 action:

📁 Projects (12): [telecode · /Users//.../telecode] ↳ [Switch active] [New session here] [api-service · /Users//.../api] ↳ [Switch active] [New session here] ...

Callback: project:cd:<id> (đổi project cho session active), project:new:<id> (vào wizard new với project đã pre-fill, skip step 3).

Phân trang 8 project / page. Buttons [← Prev] [Page 1/2] [Next →] ở dưới.

5.3 Session switch enhanced (/sessions)

Cải tiến từ /session list hiện có. Show:

  • Active marker ●.
  • Last activity (vd "2m ago", "1h ago").
  • Agent badge (🤖 / ⚡).
  • Tap = switch.
📋 Sessions (3): [● refactor-auth · 🤖 · 2m ago] [ debug-api · 🤖 · 1h ago] [ mobile-ui · ⚡ · 3h ago] [+ New session]

Callback: session:switch:<id>, session:new (vào wizard).

7. DAG execution plan

Sub-agents chạy parallel theo phụ thuộc. SDD viết song song trong cùng DAG.

Phase A — Shared infra (parallel, không phụ thuộc nhau)

  1. A1: callback-router.ts + test
  2. A2: conversation-storage.ts + test + schema migration
  3. A3: reply-builders.ts + test (skeleton, các builder cụ thể fill ở phase B)
  4. A4: commands-registry.ts + keyboard-actions.ts

Phase B — Feature wiring (chạy sau A, parallel với nhau)

  1. B1 (depends A1, A3): refactor /sessions handler dùng router + builder (§5.3)
  2. B2 (depends A1, A3): refactor /projects picker với pagination (§5.2)
  3. B3 (depends A1, A2, A3): wizard newSession + test full flow (§5.1)
  4. B4 (depends A4): boot wiring trong bot.ts — apply commands, menu button, install conversations plugin

Phase C — Consolidate

  1. C1: run full test suite, manual smoke test (tap qua Telegram thật)
  2. C2: scope completeness check theo §8 acceptance criteria
  3. C3: senior review qua Opus 4.7 (với Context7 tech freshness check)
  4. C4: update SDD docs/design/ux-telegram-widgets.html với verification results
  5. C5: update README.md (bảng lệnh + workflow section)

8. Acceptance criteria

  • Slash menu hiện đủ 8 command với mô tả tiếng Việt khi user gõ /
  • Menu button "Menu" hiện cạnh paperclip, tap mở list command
  • 6-button reply keyboard hiện persistent, mỗi tap dispatch đúng command tương ứng
  • Reply keyboard tự ẩn khi vào wizard, khôi phục sau khi exit
  • /new wizard flow 3 step (agent → project → label) hoạt động end-to-end, tạo session thật trong DB
  • Wizard cancel button hoạt động ở mọi step
  • Wizard label validation từ chối input sai format (vd có space, > 40 chars)
  • Daemon restart giữa wizard → state restore, user gõ tiếp được
  • /projects picker show inline list, mỗi project có [Switch active] + [New session here], pagination >8 projects
  • /sessions show active marker ●, last activity, agent badge, tap switch
  • CallbackRouter dispatch theo ns:action, có test unit cover unknown handler + error in handler
  • ReplyBuilders chấp nhận extraButtons param, có test snapshot
  • Conversation storage table tạo idempotent (chạy nhiều lần không lỗi)
  • All tests pass (npm test) — không break test cũ
  • Backward compat: /session new ..., /session switch ... v.v. vẫn chạy được như trước
  • README updated với UI mới
  • SDD viết xong với verification section
  • Senior review (Opus 4.7) verdict APPROVED, 0 finding P0–P3 còn lại

9. Risk register

RiskSeverityMitigation
callback_data vượt 64 bytes (giới hạn Telegram) P2 Dùng id ngắn (uuid 8 chars), không nhét path. Test có 1 case verify length < 64.
Conversation plugin phá flow command cũ P2 Conversation chỉ trigger qua ctx.conversation.enter("newSession") explicit. Command khác không bị intercept.
Reply keyboard text trùng nội dung user gõ thường ngày P2 Dùng emoji prefix 📋 Sessions — user gõ tay "Sessions" không match. Match exact string trong handler.
Wizard state cũ trong DB không tương thích version mới sau update P2 Plugin có version param. Bump version → plugin tự discard state cũ. User chỉ mất state wizard dở dang.
Persistent keyboard không hiển thị trên Telegram desktop cũ P3 Telegram Desktop < 4.6 không support is_persistent. Fallback: vẫn show keyboard nhưng dùng resize_keyboard (non-persistent on old client) — degrade gracefully.
User gõ /start giữa wizard → mất context P2 Conversations plugin tự exit khi gặp non-matching update. Bot reply: "Wizard hủy, dùng /new để bắt đầu lại". Acceptable.
