Plan · Telecode v1.0

Cross-platform & multi-agent

Đóng nốt T3 carry-over, mở registry adapter, hỗ trợ Linux + Windows native, và thêm 2 agentic CLI (Codex, Cursor) bên cạnh Claude + Kiro hiện hữu.

Target version · v1.0 Owner · dangkhoi@users.noreply.github.com Estimated effort · 10–12 ngày Phases · 7 (P0–P6) Status · Decisions chốt, chờ approve để implement

TL;DR

Telecode hiện ship v0.8 (172/172 tests, chỉ chạy macOS, hỗ trợ Claude + Kiro). Plan này đưa lên v1.0: dọn nốt 6 items T3 carry-over, refactor adapter registry sang open-set, hỗ trợ chạy native trên Linux (systemd) và Windows 11 (NSSM), thêm 2 adapter Codex CLI + Cursor CLI, đóng 5 v0.6 P2 hardening items. Antigravity skip (GUI-first, headless chưa support — đợi 6 tháng).

Ưu tiên dọn trước khi thêm: P0 (T3) + P1 (foundation refactor) là blocker cho mọi phase sau. P6 hardening có thể parallel với P3/P4.

2. Goals & Non-goals

Goals

  • G1 — Đóng 100% T3 backlog: 2 nút wizard + 3 Tier 3 features (#7/#8/#9) + wizard-aware auto-switch.
  • G2 — Adapter registry open-set: thêm adapter mới chỉ cần 1 file + 1 dòng register, không touch types.ts/config.ts.
  • G3 — Native Linux support: systemd --user service, no WSL.
  • G4 — Native Windows 11 support: NSSM service (hoặc node-windows), no WSL.
  • G5 — Codex CLI adapter (OpenAI): app-server JSON-RPC, built-in approvalPolicy.
  • G6 — Cursor CLI adapter: ACP (Agent Client Protocol) qua stdio, session/request_permission.
  • G7 — Hardening: HMAC gate token, hook server drain, daemon lockfile, list-sessions cache.

Non-goals

  • Antigravity adapter — Google ra mắt 19/05/2026, CLI Go-based GUI-first, headless mode chưa support (xác nhận từ Google Cloud Blog “Choosing Antigravity or Gemini CLI”). Đợi 6 tháng review lại.
  • IDE integration — User chỉ chấp nhận CLI. Không build VS Code extension, không tích hợp Cursor IDE / Antigravity desktop.
  • Persistent buffer qua daemon restart — Đã document out-of-scope ở v0.8, giữ nguyên.
  • Multi-user / team mode — Telecode vẫn single-user local daemon.
  • WSL fallback installer — Vì cả Kiro CLI và Codex CLI đều có native Windows binary, không cần fallback.

6. Phase 3 — Codex CLI adapter

Effort 2d Approval native

OpenAI Codex CLI (Rust, cross-platform) có sẵn JSON-RPC app-server + approvalPolicy built-in — fit pattern Kiro nhưng đơn giản hơn vì không cần hook bridge.

P3.1 · Interface

  • File mới: src/agents/codex.ts — class CodexAdapter implements AgentAdapter.
  • kind = 'codex', displayName = 'Codex', badge = '🅒'.
  • Config: command (default codex), model (default gpt-5.1-codex), effort (medium), sandboxPolicy.
  • Auth: native — telecode KHÔNG xử lý API key, KHÔNG đọc OPENAI_API_KEY, KHÔNG trigger auth flow. Codex CLI phải được user login sẵn (qua codex login hoặc env var ở shell trước khi start daemon). Telecode chỉ spawn binary và assume đã sẵn sàng. Nếu Codex CLI bị unauth → adapter trả error event, user fix bên ngoài. Doc README ghi rõ pre-requisite.

P3.2 · Lifecycle

  • Spawn codex app-server qua execa, giữ stdio JSON-RPC.
  • Init: gọi initialize, tạo thread qua thread/new.
  • Per turn: turn/start với: 
    {
  "threadId": "...",
  "input": [{ "type": "text", "text": userPrompt }],
  "cwd": session.cwd,
  "approvalPolicy": "unlessTrusted",
  "sandboxPolicy": {
    "type": "workspaceWrite",
    "writableRoots": [session.cwd],
    "networkAccess": true
  },
  "model": cfg.model,
  "effort": cfg.effort
}
    (Decision: networkAccess: true mặc định cho UX tốt — Codex có thể fetch package, gọi API. ApprovalBroker vẫn chặn mọi tool action qua approvalPolicy: unlessTrusted.)
  • Listen notifications: turn/itemAdded (text/tool_call), turn/itemUpdated (deltas), command/exec/outputDelta (cho streaming exec). Map sang AgentEvent.
  • Approval: khi Codex gửi turn/permissionRequest, route qua ApprovalBroker.ask() → reply turn/permissionResponse. Không cần hook server riêng như Kiro — protocol có sẵn.

P3.3 · Test

  • Mock JSON-RPC server qua node:net hoặc spawn fake binary echo JSON-RPC. Verify lifecycle: init → turn → exit.
  • Approval test: fake permission request → broker.ask → response gửi đúng id.

7. Phase 4 — Cursor CLI adapter

Effort 2d ACP protocol

Cursor CLI (agent) hỗ trợ ACP — JSON-RPC over stdio với session/request_permission built-in. Cross-platform.

P4.1 · Interface

  • File mới: src/agents/cursor.ts — class CursorAdapter implements AgentAdapter.
  • kind = 'cursor', displayName = 'Cursor', badge = '✦'.
  • Config: command (default agent), model (default gpt-5.2 hoặc theo Cursor docs latest).
  • Auth: native — Cursor CLI có persistent auth token tự quản lý (qua cursor-agent login). Telecode KHÔNG handle login, KHÔNG mở browser, KHÔNG lưu credentials. Skip authenticate step trong ACP handshake nếu token đã có (Cursor sẽ tự load). Nếu chưa login → ACP server trả error, adapter surface lên Telegram với hint Chạy 'cursor-agent login' trước khi dùng adapter này. Doc README ghi rõ pre-requisite.

P4.2 · Lifecycle (ACP)

  • Spawn agent acp qua execa.
  • JSON-RPC handshake:
    1. initialize với clientCapabilities: { fs: { readTextFile: false, writeTextFile: false }, terminal: false }.
    2. authenticate với methodId: 'cursor_login'.
    3. session/new với cwd: session.cwd, mcpServers: [] → nhận sessionId.
    4. session/prompt với user input → bắt đầu turn.
  • Listen session/update notifications: agent_message_chunk (text stream), tool_call events. Map sang AgentEvent.
  • Approval: khi nhận session/request_permission, route qua ApprovalBroker.ask() → respond với { outcome: { outcome: 'selected', optionId: 'allow-once' | 'allow-always' | 'deny' } }.

P4.3 · Test

  • Mock ACP server stub trong tests. Verify protocol compliance (initialize → authenticate → session/new → session/prompt → updates → result).
  • Permission flow: stub gửi session/request_permission → broker → response gửi đúng id.

8. Phase 5 — Windows support

Effort 3–3.5d Trickiest

Windows 11 native — không cần WSL. Kiro CLI có native installer, Claude SDK + Codex + Cursor đều cross-platform. Tricky chính là service installer + Kiro hook integration.

P5.1 · Kiro Windows POC verify trước khi code installer

Trước khi code installer, POC 3 điểm tích hợp Telecode ↔ Kiro trên Windows VM:

  1. Agent config path: Kiro Windows đọc %USERPROFILE%\.kiro\agents\? Verify bằng kiro-cli doctor + tạo manual telecode.json + chạy kiro-cli chat --agent telecode --no-interactive "test".
  2. preToolUse hook command shell: Doc Kiro cho ví dụ POSIX shell. Trên Windows, hook command có được parse bằng shell nội bộ Kiro, hay phải wrap qua powershell -Command "..." / cmd.exe /c ...? Test với hook đơn giản echo hello > %TEMP%\kiro-hook.log.
  3. Gate script invocation: kiro-gate.ts shebang #!/usr/bin/env node không work trên Windows. Agent JSON config phải emit "command": "node", "args": ["C:\\Users\\...\\kiro-gate.js"] tường minh. Verify telecode đã làm vậy chưa.

POC output: short report (Markdown) ghi 3 findings + fixes cần áp vào src/agents/kiro-agent-config.ts.

P5.2 · Service installer (PowerShell + NSSM)

Decision: lean & portable — telecode KHÔNG bundle nssm.exe. User tự cài NSSM qua winget trước khi chạy installer. Doc README có pre-requisite section.

  • Pre-requisite (user tự làm): 
    winget install NSSM.NSSM
# hoặc: choco install nssm
# hoặc download manual từ nssm.cc
  • scripts/install-windows.ps1 verify NSSM tồn tại (Get-Command nssm) → fail-fast với hint nếu chưa cài. Sau đó:
    1. Prompt token + chat ID, ghi %USERPROFILE%\.telecode\config.yaml.
    2. nssm install Telecode "C:\Program Files\nodejs\node.exe" "<install-dir>\dist\index.js".
    3. nssm set Telecode AppEnvironmentExtra TELECODE_HOME=%USERPROFILE%\.telecode.
    4. nssm set Telecode AppRestartDelay 5000, nssm set Telecode ObjectName LocalSystem (hoặc current user nếu user-scope).
    5. nssm start Telecode.
  • scripts/uninstall-windows.ps1: nssm stop Telecode + nssm remove Telecode confirm.
  • Alternative considered: node-windows npm package — pure JS, không cần NSSM. Trade-off: node-windows dễ cho user (no pre-req) nhưng kém mature cho crash-restart. Reject: user thích lean & portable hơn auto-magic; NSSM phổ biến + 1 lệnh winget.
  • Alternative fallback: Task Scheduler XML với OnLogon trigger — không có crash-restart nhưng zero dependency. Doc README đề cập như option “lightweight” cho user không muốn NSSM.

P5.3 · Source code Windows tweaks

  • SIGBREAK handler trong src/index.ts bên cạnh SIGINT/SIGTERM.
  • src/agents/kiro.ts: candidate runtime paths Windows-specific (%USERPROFILE%\AppData\Roaming\nvm, %USERPROFILE%\.cargo\bin, %LOCALAPPDATA%\Programs\Python\..., %USERPROFILE%\AppData\Roaming\npm).
  • src/agents/kiro-agent-config.ts: emit hook command theo platform (POC findings từ P5.1).
  • /screenshot Windows path (đã cover ở P1.3).

P5.4 · Smoke test

  • Windows 11 VM (UTM hoặc Parallels). Install qua PowerShell script. Boot daemon, gửi /new qua Telegram, tạo session Claude + session Kiro, verify approval flow + auto-switch.
  • Reboot VM → daemon tự start qua NSSM, sessions resume (theo SQLite state).

9. Phase 6 — Hardening (v0.6 P2 carry-over)

Effort 1–1.5d Parallel với P3/P4

5 hardening items đã document defer ở v0.6. Có thể chạy song song không block các phase khác.

  • P6.1 — Per-boot HMAC token trên TELECODE_GATE_URL: generate random 32 bytes lúc daemon boot, embed vào env var truyền cho kiro-cli, hook server verify HMAC. Phòng same-user different-process spoof.
  • P6.2 — KiroHookServer.stop() drain in-flight broker.ask: trước khi close server, wait pending approval (timeout 30s) hoặc reject all với “shutdown”.
  • P6.3 — Daemon singleton lockfile: ~/.telecode/daemon.lock giữ PID, boot check liveness, fail nếu đã có daemon đang chạy. Tránh dev vs launchd race.
  • P6.4 — Cache kiro-cli --list-sessions per cwd: hiện gọi lại mỗi /sessions, cache 30s.
  • P6.5 — Test coverage cho writeKiroTelecodeAgent: idempotency, atomic rename, mode-0o600 (skip assertion trên Windows).

11. Risks & open questions

R1 — Antigravity headless support

Google có thể release headless mode cho Antigravity CLI trong 3–6 tháng (theo trend của Gemini CLI). Nếu xảy ra trước khi v1.0 ship, có nên gộp vào không? Decision đề xuất: KHÔNG. Antigravity adapter sẽ là plan riêng v1.1 — registry open-set ở P1 đủ để add adapter mới không phải re-plan.

R2 — Cursor CLI auth flow trên daemon

Cursor authenticate với cursor_login mở browser — daemon mode không có browser. Cần verify Cursor có persistent auth token (qua ~/.cursor/auth.json hoặc tương tự) để adapter chỉ cần re-authenticate nếu token hết hạn. POC nhanh ở đầu P4.

R3 — Codex CLI tốc độ thay đổi API

Codex CLI đang ở pre-1.0 (rust v0.75 hiện tại). API turn/start có thể đổi. Mitigation: pin version qua install script, dùng Context7 verify version latest trước implement, document required version trong README.

R4 — Windows file lock semantics

SQLite WAL mode + atomic rename hoạt động khác trên Windows (rename qua file đang mở fail). Cần verify better-sqlite3 handle đúng. POC: chạy unit tests SessionStore trên Windows VM.

R5 — NSSM dependency

NSSM cần cài qua winget hoặc bundle. Nếu user không có admin rights, winget có thể không install được. Mitigation: bundle nssm.exe trong release zip (NSSM là BSD-licensed, OK redistribute). Fallback: dùng Task Scheduler XML với OnLogon trigger (no crash-restart, nhưng đơn giản hơn).

12. Acceptance criteria

A1 — Functional

  • Tất cả 6 T3 items có code + test + verify thủ công qua Telegram.
  • Tạo session với kind: codex hoặc kind: cursor qua wizard /new hoạt động end-to-end.
  • Telecode chạy native trên Ubuntu 24.04 + Windows 11 (verified qua VM smoke test).
  • Service auto-restart sau crash trên cả 3 OS.

A2 — Code quality

  • Adapter registry: thêm adapter giả lập “mock” chỉ touch 1 file mới + 1 dòng register. Verify bằng test.
  • Zero '/' hoặc ':' hardcoded path/delimiter ngoài node:path API.
  • Tất cả tests cũ vẫn pass (≥172/172). Tests mới ≥40 cases cho 2 adapter + 10 cases cho T3 items + 8 cases cho Windows-specific utils.

A3 — Documentation

  • README có 3 install sections (macOS / Linux / Windows) ngang hàng.
  • SDD HTML tại docs/design/telecode-v1.0-cross-platform-multi-agent.html cover đầy đủ design decisions, file changes, verification.
  • Tech freshness table: 4 adapter (Claude / Kiro / Codex / Cursor) version + API verified qua Context7.

A4 — Senior review

  • Opus 4.7 senior review pass: 0 actionable [P0]–[P3] findings remaining.
  • Scope completeness check: 100% deliverables ✅.
  • Tech freshness check: tất cả dependency latest stable hoặc pinned với lý do.

13. Test strategy

Unit

  • Mỗi adapter mới: stub binary (Codex JSON-RPC, Cursor ACP) qua node:child_process mock — verify protocol compliance, approval routing, event mapping.
  • Adapter registry: register/unregister, duplicate kind error, list ordering.
