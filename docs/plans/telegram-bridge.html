1. Mục tiêu

Build 1 daemon chạy local trên macOS, đóng vai trò cầu nối hai chiều giữa Telegram và các coding agent (Claude Code, Kiro):

  • Từ Telegram: gửi prompt → agent thực thi trên máy → kết quả stream về chat.
  • Từ agent: notify ra Telegram khi cần approve tool ngoài policy, khi xong task, khi có lỗi.
  • Multi-session đồng thời: có thể chạy song song nhiều session — vd "Claude #1 đang refactor module A", "Claude #2 đang viết test cho module B", "Kiro #1 đang fix bug ở project khác" — mỗi session độc lập về context, agent, project.
  • Đổi agent linh hoạt: khi tạo session chọn claude hoặc kiro; sau này extend thêm Cursor / Codex / khác qua adapter interface.
  • Single user — chỉ Telegram ID của mình mới interact được.

Không thuộc scope phase này

  • Multi-user / team mode.
  • Cloud-hosted (vẫn local).
  • Voice / file upload phức tạp (chỉ text + screenshot reply trước mắt).

2.1 Các module chính

Bot Router

grammY + long-polling. Whitelist 1 user ID. Parse commands (/session, /cd, /new...) và plain text prompts.

Session Store

SQLite (better-sqlite3, WAL mode). Tables: projects, sessions (id, label, agent, project_id, chat_id, sdk_session_id, status, created_at), tool_log, approvals. Mỗi chat có active session_id.

SessionManager

Quản vòng đời session: tạo, switch active, list, close, persist resume id. Mỗi session có 1 mutex để serialize prompts trong cùng session. Nhiều session khác nhau chạy song song độc lập.

Agent Router

Dispatch prompt tới adapter đúng theo session.agent. Interface AgentAdapter: start(opts), send(prompt), interrupt(), onEvent(). Extensible: Cursor / Codex adapter sau này chỉ cần implement interface.

Claude Adapter

@anthropic-ai/claude-agent-sdk với query() streaming. Pass options.canUseTool, options.hooks, options.resume = sessionId, options.settingSources: ['user','project','local'] — đồng nhất với local CLI behavior.

Kiro Adapter

Spawn kiro-cli chat --no-interactive --agent telecode --trust-all-tools qua execa với env TELECODE_SESSION_ID + TELECODE_GATE_URL. Stream stdout → strip ANSI → notifier edit Telegram message. Sau khi xong, đọc --list-sessions để persist UUID cho --resume-id lần sau. Permission qua preToolUse hook bridge → ApprovalBroker (mid-session interactive approve y hệt Claude).

ApprovalBroker

In-process map <requestId → Promise resolver>. canUseTool callback push pending vào đây, gửi Telegram inline button, await user tap, resolve {behavior: 'allow'|'deny'}. Có timeout fallback.

Notifier

Format event thành Telegram message (markdown). Edit message tại chỗ cho streaming output. Split khi > 3500 ký tự. Debounce + rate-limit để tránh Telegram 429.

Policy Engine

Trong canUseTool: match tool call vs allow/deny pattern config. Allow → auto-resolve. Deny → reject ngay. Otherwise → forward ApprovalBroker. Tất cả in-process, không touch project files.

3. Permission & Notification flow

Mode: interactive approve qua canUseTool + inline policy engine. Đây là pattern modern, idiomatic theo Claude Agent SDK (verified qua Context7).

  1. Mỗi query() được spawn với options.canUseTool = ApprovalBroker.handle.
  2. Khi Claude muốn dùng tool, SDK gọi callback async với (toolName, input).
  3. PolicyEngine match:
    • Allow pattern (vd Read, Grep, Edit({{cwd}}/**)) → resolve {behavior: 'allow', updatedInput: input} ngay, kèm notify Telegram “🔧 Edit foo.ts” (fire-and-forget).
    • Deny pattern (vd Bash(rm -rf*), Bash(git push --force*)) → resolve {behavior: 'deny', message: '...'} ngay.
    • Otherwise → ApprovalBroker tạo pending request, gửi Telegram inline button [Allow once] [Allow always] [Deny] → await tap → resolve.
  4. Hooks (PreToolUse/Notification/Stop) đăng ký inline qua options.hooks chỉ để logging/notify, không quyết định permission (vì canUseTool đã đảm nhiệm).
  5. Hook Stop → notify “✅ Done” + tóm tắt 3 dòng cuối + cost/duration.
Tại sao không dùng .claude/settings.json? SDK chấp nhận options.hooks + options.canUseTool truyền vào trực tiếp ở runtime — gọn, không ghi file rác vào project repo của user, không xung đột với config sẵn có của user trong project. Toàn bộ policy + approval state sống in-process trong daemon.
Timeout fallback: Nếu user không tap button trong N giây (default 5 phút), ApprovalBroker tự resolve deny để tránh Claude session treo. Configurable per-tool (vd Bash có thể chờ lâu hơn Read).

4. Multi-session model

Một session = một thread hội thoại độc lập, gồm:

  • label: tên user-friendly, vd claude-refactor, kiro-bugfix, claude-2.
  • agent: claude | kiro | (tương lai) cursor, codex...
  • project: path workspace mà agent chạy bên dưới.
  • sdk_session_id: id để resume context (chỉ Claude có; Kiro coi mỗi prompt là 1 session IDE).
  • status: idle | running | waiting_approval.

Mỗi chat Telegram có 1 active session tại 1 thời điểm — plain text message gửi vào session đó. Có thể switch giữa các session bằng /session switch. Sessions của các project / agent khác nhau chạy song song độc lập trong daemon (mỗi session 1 mutex; không block lẫn nhau).

Ví dụ flow: 
/session new claude refactor ~/work/api      → tạo session "refactor" agent=claude, project=api
hãy refactor module auth                      → gửi prompt vào "refactor"
/session new kiro bugfix ~/work/mobile        → tạo session "bugfix" agent=kiro, project=mobile
/session switch refactor                       → quay lại session "refactor"
status thế nào rồi?                            → tiếp tục chat trong "refactor", có resume context
/session list                                  → liệt kê cả 2 session + status

8. Cấu trúc config

Tách 2 file: config.yaml (read-only sau khi user setup, daemon không bao giờ ghi) và policy.yaml (live, daemon có thể append qua /allow//deny; user cũng edit tay được).

# ~/.telecode/config.yaml  (user edits, daemon read-only)
telegram:
  bot_token: ${TELEGRAM_BOT_TOKEN}         # env var, không commit
  allowed_user_ids: [123456789]            # koi (@u2526)
daemon:
  log_dir: ~/.telecode/logs
  approval_timeout_sec: 300                # canUseTool timeout fallback → deny
  workspace_scan:                          # auto-register project khi boot
    roots: [~/Documents/workspaces]
    max_depth: 1                           # chỉ subfolder cấp 1
    exclude: [node_modules, .git, dist, build]
agents:
  claude:
    binary: claude                         # PATH lookup
    setting_sources: [user, project, local]  # đồng nhất local CLI behavior
  kiro:
    binary: kiro
    default_mode: agent                    # ask | edit | agent
defaults:
  agent: claude
session_switch_preview_lines: 3            # show 3 last lines khi /session switch
# projects: auto-populated từ workspace_scan; có thể override/add tay ở đây

# ~/.telecode/policy.yaml  (live; daemon + user co-edit, atomic write)
allow:                                     # auto-resolve in canUseTool
  - Read
  - Grep
  - Glob
  - "Edit({{project_dir}}/**)"
  - "Write({{project_dir}}/**)"
  - "Bash(npm test*)"
  - "Bash(npm run *)"
  - "Bash(git status*)"
  - "Bash(git diff*)"
  - "Bash(git log*)"
deny:                                      # auto-deny in canUseTool
  - "Bash(rm -rf*)"
  - "Bash(git push --force*)"
  - "Bash(curl * | sh*)"
  - "Edit(~/.ssh/**)"
  - "Edit(~/.aws/**)"
# everything else → Telegram inline button

Race condition giữa user-edit và daemon-write giải quyết bằng: daemon dùng fs.watchFile reload khi user save; mọi write từ daemon dùng atomic rename (tmp file + rename); SQLite vẫn là source of truth cho "always allow" trong session hiện tại, policy.yaml chỉ là persistence layer.

M0 — Foundation (1 buổi)

  • Verify + pin exact version các lib qua Context7 (claude-agent-sdk, grammy, better-sqlite3, execa, pino, zod). Ghi vào SDD.

  • BotFather wizard trong install script: hướng dẫn user mở Telegram → @BotFather → /newbot → paste token vào ~/.telecode/.env (chmod 600).
  • Workspace scanner: scan ~/Documents/workspaces/* depth 1, auto-register làm project.

M1 — Telegram round-trip + SessionManager (1-2 buổi)

  • grammY bot connect, whitelist user_id 123456789, /start + /status.
  • Project commands: /projects (auto-populated từ scan), /add, /cd.
  • Session commands: /session new|list|switch|rename|close|reset với inline keyboard cho quick switch.
  • Switch preview: /session switch <label> reply "📍 [label]" + 3 dòng cuối của transcript session đó để gợi nhớ context.
  • Echo bot — plain text → "[session-label] echo: ..." (chưa qua agent, validate routing đúng).
  • Per-session mutex framework sẵn sàng (chưa wire agent).

M2 — Claude adapter + streaming (2 buổi)

  • Spawn Claude session via SDK query() với cwd, settingSources: ['user','project','local'], resume.
  • Stream assistant messages → edit Telegram message (debounce 700ms, token-bucket rate-limit).
  • Lưu & reuse session_id để resume cross-restart.
  • /session reset, /stop (AbortController) hoạt động.
  • Multi-session smoke test: 2 sessions Claude khác project chạy song song không block.

M3 — canUseTool + Policy + interactive approve (1-2 buổi)

  • ApprovalBroker: Map<requestId, {resolve, reject, timer, sessionId}>, gửi Telegram message với inline buttons [Allow once] [Allow always] [Deny] + label session để biết approval thuộc session nào.
  • PolicyEngine: glob pattern matching; load + watch policy.yaml; /allow//deny atomic-append.
  • Wire canUseTool vào Claude adapter: policy → broker → resolve back.
  • Register options.hooks inline (PreToolUse/Stop) cho logging vào tool_log + notify (không quyết định permission).
  • Timeout fallback: hết approval_timeout_sec → auto-deny + Telegram báo.
  • /status logs [n] tail từ tool_log table cho session active.

M4 — Kiro adapter (v0.6: kiro-cli headless + preToolUse bridge)

  • Spawn kiro-cli chat --no-interactive --agent telecode --trust-all-tools [--resume-id ...] với env TELECODE_SESSION_ID + TELECODE_GATE_URL; cwd = project path.
  • Stream stdout chunk-by-chunk, strip ANSI/cursor codes, emit text event → notifier edit Telegram message (cùng pipeline với Claude).
  • Boot tasks: writeKiroTelecodeAgent sinh ~/.kiro/agents/telecode.json (preToolUse hook trỏ về dist/cli/kiro-gate.js); KiroHookServer bind 127.0.0.1 ephemeral port; gate script existence assertion fail-loud.
  • Hook flow: kiro-cli → gate script → POST /kiro-hook → daemon PolicyEngine.decide → allow/deny ngay hoặc ask qua ApprovalBroker (Telegram inline button) → exit 0/2 (deny kèm stderr cho LLM).
  • Cross-restart resume: sau mỗi prompt, parse kiro-cli chat --list-sessions để lấy session UUID, persist vào sessions.sdk_session_id.
  • /screenshot helper qua screencapture với friendlier error nếu Screen Recording permission missing.
  • E2E: /session new kiro x ~/work/api + "đọc file README" → Telegram nhận approval button cho read, tap allow → Kiro thực thi, output stream về Telegram.

M5 — Hardening (1 buổi)

  • Crash recovery: launchd KeepAlive + on-boot scan sessions WHERE status='running' → mark 'interrupted' + notify per-session.
  • Secret scrubbing: pino redact (bot_token, Authorization, ANTHROPIC_API_KEY) + notifier regex scrub (\d+:[A-Za-z0-9_-]{35}, sk-ant-*).
  • Log rotation: pino-roll daily, retention 7 ngày.
  • Per-session mutex enforce: prompt mới khi session đang busy → "⏳ busy, /stop hoặc enqueue?".
  • Streaming message rotation (post mới mỗi 50 edits / 3500 chars / 5 phút).
  • Atomic policy.yaml write (tmp + rename); reload trên fs.watchFile.
  • E2E test script: gửi prompt từ Telegram → verify code thay đổi đúng project, đúng session.
  • README + install guide (BotFather setup, multi-session usage, troubleshooting).
