Plan · Telecode v1.1

Streaming UX redesign

Từ "firehose mọi event" sang summary-first + mode toggle + smart rendering + agentic compression. Persona-aware streaming cho Telegram-first user.

Target version · v1.1 Owner · dangkhoi@users.noreply.github.com Estimated effort · 10–11 ngày Phases · 5 (A–E) Status · Approved, executing

TL;DR

Telecode v1.0 stream MỌI event về Telegram → firehose noise + format khó đọc. v1.1 ship: (A) fix 2 real bugs + quick wins, (B) 4 verbosity modes (default = summary), (C) smart rendering (code-fence, diff stats, collapse repeated tools), (D) agentic compression (reuse session để auto-summarize), (E) single rolling activity indicator. Backward compat 100% — user cũ upgrade không break.

Killer feature (D): thay vì rule-based truncate, telecode inject prompt "tóm tắt 2 dòng" vào session đang chạy → reply summary thay raw 200-dòng stdout. Cost ăn vào budget của session, không cần separate API key.

2. PO/UX mindset

2.1 Personas + mental model

PersonaKhi nàoCần thấy% use case
On-the-goPhone, đi bộ / họp / lái xeApproval + done + errors + final summary~50%
Casual monitorPhone, đang làm việc khác+ tool calls chính (Bash/Edit) + results compact~30%
FocusedDesktop, theo dõi task+ thinking + text response + status~15%
DebuggingDesktop, troubleshoot+ raw stdout + all chunks (current behavior)~5%

v1.0 serve mọi persona bằng cùng firehose → fail persona 1 (80% combined). v1.1 default cho persona 1, knob để escalate.

2.2 Design principles

  1. Telegram-first: user đang trên phone, glance-mode. Mỗi notification phải có actionable value.
  2. Summary-by-default: hiển thị ÍT, user opt-in để thấy nhiều.
  3. Agent IS the formatter: dùng AI để tóm tắt thay rule-based truncate. Telecode đã có 4 agents — leverage them.
  4. Edit > append: cùng 1 message edit khi possible (Telegram cho 30 edit/min). Giảm noise.
  5. Friendly > technical: Read · notifier.ts > Read — {"file_path":"..."}.
  6. Backward compat: user v1.0 upgrade không break. Verbose mode = current behavior.

5. Phase B — Mode system

Effort 2d Default = summary

4 verbosity modes per-session + per-chat default.

B.1 — Mode definition

ModeIconShowsUse case
summary (default)🎯approval, done (with AI summary), errors, final results onlyOn-the-go, glance
normal📝+ tool_use compact + tool_result compactCasual monitor
thinking🧠+ thinking blocks (Claude with 🧠 prefix) + Cursor thoughts (labeled)Focused / learning
verbose🔬+ raw text chunks + status events + full preview (current v1.0 behavior)Debugging

B.2 — Storage

  • DB migration: thêm column sessions.verbosity_mode TEXT DEFAULT 'summary' (NULL → falls back to chat default).
  • DB migration: thêm column chat_settings.default_mode TEXT DEFAULT 'summary' hoặc record trong chat_settings table mới.
  • Idempotent ALTER TABLE IF NOT EXISTS pattern như v1.0 schema migration.

B.3 — Commands

  • /mode — show current session mode + chat default + list options inline keyboard [🎯 Summary] [📝 Normal] [🧠 Thinking] [🔬 Verbose]
  • /mode <name> — set per-session
  • /settings mode <name> — set chat default (affects new sessions)
  • Callback handlers in router.ts

B.4 — Dispatch filter

  • Trong commands/index.ts dispatch — wrap event filtering theo mode trước khi gọi notifier.
  • Mode-aware filter table: 
    function shouldEmit(event: AgentEvent, mode: VerbosityMode): boolean {
  switch (event.type) {
    case 'approval': return true; // always
    case 'error': return true;
    case 'done': return true;
    case 'tool_result': return mode !== 'summary' || !event.success;
    case 'tool_use': return mode !== 'summary';
    case 'text': return mode !== 'summary'; // summary suppresses streaming text
    case 'thinking': return mode === 'thinking' || mode === 'verbose';
    case 'status': return mode === 'verbose';
    default: return true;
  }
}
  • Edge case: summary mode mà session không emit done summary → user "im lặng". Mitigation: nếu task ran >10s không có output, send fallback ⏳ Working... (10s) ephemeral.

B.5 — Migration

  • v1.0 user upgrade: existing sessions chưa có verbosity_mode → default summary. Breaking change for power users. Mitigation: lần đầu boot v1.1, telecode send 1 message "📢 Telecode v1.1: mode mặc định giờ là Summary. Muốn behavior cũ: /settings mode verbose"

6. Phase C — Smart rendering

Effort 2d

Code-fence detection + diff-aware Edit + collapse repeated tools.

C.1 — MarkdownV2 với escape helper

  • File mới: src/bot/markdown.ts:
    • escapeMd(s: string): string — escape _*[]()~`>#+-=|{}.! per Telegram MarkdownV2 spec
    • codeBlock(s: string, lang?: string): string — wrap in ```lang\n{s}\n``` (no escape inside code)
    • inlineCode(s: string): string — wrap in `s` (escape backticks inside)
  • Notifier param parse_mode: 'MarkdownV2' cho text events.

C.2 — Auto code-fence detection

  • Heuristics:
    • Text chứa { at line start AND } at end + "field": pattern → wrap ```json
    • Text chứa lines bắt đầu bằng + hoặc - AND @@ hunks → ```diff
    • Text chứa at Function / at Object stack pattern → ```
    • Text chứa $ / > shell prompt → ```bash
    • Fallback: text > 200 chars + chứa newline → ``` (mono spacing readable)
  • Tests: per heuristic + edge cases (text với JSON-like word "bạn nói {hello}").

C.3 — Diff stats cho Edit tool

  • Trong tool-render.ts: Edit input có old_string + new_string. Compute:
    • Lines removed = old_string.split('\n').length
    • Lines added = new_string.split('\n').length
    • Render: 📝 Edit · notifier.ts (-3 +7)
  • Bonus: nếu mode = thinking/verbose, attach button [📜 Show diff] → tap show MarkdownV2 ```diff block.

C.4 — Collapse repeated tool calls (5s window)

  • Per-session ring buffer của recent tool_use events (last 10).
  • Khi event mới đến + cùng tool name + within 5s + cùng session → edit existing message thay send new.
  • Format collapsed: 🔧 Read ×3 · notifier.ts, types.ts, reply-builders.ts ✅
  • State machine: rolling message ID lưu trong notifier scoped Map. Reset khi tool khác đến hoặc 5s timeout.
  • Test: 3 Read events within 2s → 1 edit, 3rd file appended. 4th Read after 6s → new message.

C.5 — Path collapsing

  • ~ for home dir
  • ./ for paths trong active project cwd
  • Basename only if >50 chars total → ...auth/validateToken.ts

7. Phase D — Agentic compression

Effort 3d Killer feature

Reuse session để AI-summarize. Per D2 decision: ăn cost của session (no separate API key).

D.1 — Session reinjection helper

  • File mới: src/agents/summarize.ts: 
    async function summarizeWithSession(
  manager: SessionManager,
  sessionId: string,
  content: string,
  instruction: string,  // e.g. "Tóm tắt 2 dòng"
): Promise<string> {
  // Inject hidden prompt vào session adapter
  // Pattern same as /handoff but with custom instruction
  // Return: agent text response
}
  • Mechanism: tương tự /handoff hiện có — temporary inject prompt vào next turn, capture agent text response, KHÔNG persist trong transcript.
  • Timeout 30s (agent quick response only).
  • Fallback nếu fail: trả original content.

D.2 — Auto-summarize long tool_result preview

  • Trong dispatch tool_result handler: nếu event.preview.length > 500 chars (configurable) AND mode != verbose:
    1. Send compact placeholder ⏳ Summarizing 1.2KB output... (silent edit-able message)
    2. Async call summarizeWithSession(manager, sessionId, event.preview, "Tóm tắt output trong 2 dòng tiếng Việt")
    3. Edit placeholder thành ✅ Bash · npm test\n{summary}\n[📜 Full output] [💬 Re-summarize]
  • Race protection: summarize call mutex per session (không spawn 2 song song trong cùng session).
  • Cost transparency: track cost summary trong logger + optionally show (+ $0.001) trong message.

D.3 — On-demand AI summary button

  • Mọi tool_result với full_preview attached: render button [💬 AI summary] trên message.
  • Callback summarize:tool-result:<message-id> → fetch full content from cache → reinject → edit message với summary.
  • Cache: Map<messageId, fullContent> in-memory, TTL 1h, max 100 entries (LRU).

D.4 — Auto done-summary

  • Trên done event (mode = summary OR normal):
    1. Compute task duration + cost.
    2. Inject prompt vào session: "Tóm tắt công việc vừa làm 1-2 câu, ngắn gọn."
    3. Render: ✅ Done · {duration} · {cost}\n{summary}
  • Edge case: session không respond (timeout) → fallback ✅ Done · {duration} · {cost} (current behavior).
  • Mode = verbose → skip auto-summary (verbose user thấy raw transcript đã đủ).

D.5 — Full output viewer

  • Button [📜 Full output (200 lines)] trên summarized message — tap → send original full content trong code-fence (split if >3500 chars).
  • Cache same as D.3.

8. Phase E — Activity indicators

Effort 1.5d

Single rolling progress message per session.

E.1 — Progress message lifecycle

  • Session có active turn → telecode maintain 1 progress message edit-only: 
    ⏳ [refactor-auth] Claude thinking...
        ↓ (after status event)
⏳ [refactor-auth] Reading 3 files...
        ↓ (after tool_use)
⏳ [refactor-auth] Running tests... (12s)
  • Position: pinned at recent message (no separate pin — just always edited near top).
  • Cleanup: turn done → edit progress message thành final summary OR delete (configurable per mode).

E.2 — Status event surface

  • Adapter status events giờ render vào progress message:
    • kiro_spawning → ⏳ Starting Kiro...
    • codex_turn_started → ⏳ Codex thinking...
    • cursor_spawning → ⏳ Starting Cursor...
    • cursor_plan_update → ⏳ {plan_summary}
  • Mode-aware: summary mode = always show progress (since other events suppressed); normal/thinking = show; verbose = skip (raw events đã đủ).

E.3 — Idle ping

  • Mode summary, task >30s no output → progress message updates: ⏳ Working... (30s)
  • Tránh user nghĩ daemon hang.

10. Risks & open questions

R1 — Summary mode silence

Summary mode suppress streaming text + tool_use → user "im lặng" lâu nếu task chạy lâu. Mitigation: Phase E progress indicator + idle ping. Vẫn có thể fail nếu progress message nằm trên cao xa current input. Fallback: nếu >60s không event nào notify, send ephemeral ⏳ Still working... ping.

R2 — AI summarize cost transparency

D2 decision: reuse session = ăn budget session. Có thể accidentally đắt khi user không biết. Mitigation: log cost summary lines trong pino + optional (+ $0.001) trong message footer.

R3 — Session context window pollution

Inject "Tóm tắt 2 dòng" prompt vào session đang chạy task có thể confuse agent next turn. Mitigation: dùng system message hoặc tool result injection (per Claude SDK), không inject như user message. Verify pattern /handoff hiện tại làm thế nào → reuse same mechanism.

R4 — Code-fence detection false positives

Heuristic detect JSON / diff có thể wrap nhầm normal text. Mitigation: conservative thresholds + unit test với 20+ edge cases. Failure mode = visual ugly, không break functionality.

R5 — Migration breaking change cho power users

Default mode summary = behavior thay đổi đáng kể. User v1.0 power-user có thể confused. Mitigation: first-boot v1.1 send announcement message + REASONABLE default cho new install (summary) vs preserve cho existing chat (offer choice).

R6 — Markdown escape edge cases

MarkdownV2 chặt chẽ — escape sai 1 char là Telegram trả 400. Mitigation: comprehensive escape helper + tests + fallback to plain text on parse error.
