0. v0.6 / v0.5 Addendum (Kiro rewrites)

After the v0.4 single-sweep, Context7 turned up kiro-cli v2.3+ — a headless binary separate from the kiro IDE launcher (which the v0.4 adapter spawned). Two iterations followed:

0.1 v0.5 (commit ff4a5aa) — switch to kiro-cli headless

  • Why: v0.4 Kiro adapter spawned kiro chat --reuse-window (IDE), which loaded the prompt into the Electron chat panel but had no stdout. Phase-1 "fire-and-notify" was the only option, and the user reported the panel often arrived empty when no workspace was open in the reused window.
  • What: rewrote src/agents/kiro.ts to spawn kiro-cli chat --no-interactive [--resume-id ...] [--trust-tools=...] <prompt>. Streamed stdout chunk-by-chunk into the existing text AgentEvent pipeline (notifier debounces + edits the Telegram message). Added an ANSI/cursor-code stripper (\x1b[... sequences) and a regex (Chat SessionId: <uuid>) that scrapes --list-sessions output after each prompt to persist the session UUID for cross-restart --resume-id.
  • Trade-off: --trust-tools=fs_read default was safer than --trust-all-tools but left users in a corner — Kiro asks for permission on most non-read tools and headless mode has no place to ask. v0.6 fixes this.

0.2 v0.6 (commit 8b6ddd8) — preToolUse hook bridge for Claude-parity approvals

  • Why: trust-list-at-startup is impractical because Kiro touches many tools mid-prompt; the user can't possibly know which to pre-trust. Context7 then revealed Kiro custom agents support a preToolUse hook with Claude-style exit-code semantics (0=allow, 2=block + STDERR returned to the LLM, other=warn). That's the bridge.
  • Architecture:
    • KiroHookServer (new, src/util/kiro-hook-server.ts): tiny node:http server bound to 127.0.0.1 on an ephemeral port. Exposes POST /kiro-hook.
    • writeKiroTelecodeAgent (new, src/agents/kiro-agent-config.ts): on daemon boot, idempotently writes ~/.kiro/agents/telecode.json — a kiro-cli custom agent declaring tools: ["*"], allowedTools: ["*"], and a hooks.preToolUse entry whose command is the absolute path to the gate shim.
    • src/cli/kiro-gate.ts (new bin): reads the hook event JSON from stdin, POSTs it to the daemon at $TELECODE_GATE_URL with x-telecode-session: $TELECODE_SESSION_ID, blocks on the response, exits 0 (allow) or 2 (deny — prints the reason to STDERR so the LLM sees it). Bundled into dist/cli/kiro-gate.js with chmod +x.
    • Kiro adapter now spawns kiro-cli chat --no-interactive --agent telecode --trust-all-tools [--resume-id ...] [--model ...] <prompt> with the two env vars set. --trust-all-tools only bypasses kiro-cli's built-in approval prompt (which has no TTY anyway under --no-interactive); the hook still fires for every tool call.
    • Daemon handler: looks up the telecode session by id (unknown → deny), runs PolicyEngine.decide(toolName, input, {projectDir}). Auto-allow / auto-deny return immediately. Otherwise calls ApprovalBroker.ask — the same path Claude uses — which posts [Allow once] [Allow always] [Deny] to Telegram and awaits the tap. allow_always appends to policy.yaml. Response is sent via x-telecode-decision + x-telecode-reason headers.
  • Cross-agent policy: PolicyEngine.renderInputForMatch learns Kiro shapes. Claude's Bash({command}) + Edit({file_path}) still work; Kiro adds shell({command}), execute_bash({command}), and read/write/fs_read/fs_write which use either {path} or batched {operations:[{path,...}]}. Senior review iter 1 caught that the operations[] shape wasn't unwrapped — deny: ["read(~/.ssh/**)"] would have silently no-op'd. Patched + 2 regression tests added.
  • Timeout grace: kiro-cli's preToolUse timeout_ms is set to approval_timeout_sec * 1000 + 10_000 so the broker is always the one that expires first and cleans up its pending map — kiro-cli won't SIGKILL the hook mid-await and orphan a Telegram button.
  • Boot-time gate-script assertion: resolveGateScript() throws loud if neither dist/cli/kiro-gate.js nor the dev fallback exists, instead of falling through to a non-existent path that would fail-closed every Kiro tool call with a confusing "daemon unreachable" deny.

0.3 Threat model (v0.6 surface)

  • HTTP gate binds 127.0.0.1 only — no LAN/external reach. node:http with explicit host arg.
  • Authn is the telecode session UUIDv4 in x-telecode-session. Practically unguessable for the single-user local daemon model. P2 follow-up: add per-boot HMAC token to TELECODE_GATE_URL for defence-in-depth against same-user-different-process attackers.
  • kiro-cli's env (including TELECODE_GATE_URL) is inherited by any child process it spawns. Acceptable for the single-user model; documented.
  • Gate script lives in dist/ at the daemon's install root. Build chmod +x'es it; tampering protection inherits from filesystem ownership.

1. Overview & diff vs plan (v0.4)

v0.4 plan implemented end-to-end. No scope cuts. Deviations:

  • Policy glob matcher uses a hand-rolled globToRegex instead of picomatch: command-style args like rm -rf* need * to span spaces and slashes (picomatch's * is single-segment by default). The custom matcher treats * as .* — closer to plan §8 expected behaviour. picomatch dep removed in v0.6.
  • Hono left out (plan §6 already marked optional).
  • Kiro adapter was phase-1 fire-and-notify per plan §9 M4 — superseded by v0.5 (kiro-cli headless) + v0.6 (preToolUse bridge). See §0 above.

3. Module-by-module design

M0 — Foundation

Context

Bootstrap, deps pinned, SQLite schema, launchd installer + BotFather wizard.

Requirements

  • Node 22 ESM, TS strict NodeNext.
  • SQLite WAL with tables projects, sessions, tool_log, approvals, chat_state.
  • launchd plist with KeepAlive, RunAtLoad, log path → ~/.telecode/logs/.
  • Workspace scanner depth 1, exclude node_modules/.git/dist/build.

Design decisions

  • Schema kept in src/session/schema.sql; build copies to dist/session/schema.sql so runtime loads via readFileSync. Test path tries dev fallback.
  • Workspace scan now records every directory at any allowed depth (fixes off-by-one vs plan).
  • Env loader is minimal hand-rolled to avoid dotenv dep.

File changes

M1 — Telegram round-trip + SessionManager

Design decisions

  • grammY + @grammyjs/runner. Whitelist middleware drops non-allowed user IDs before any other handler.
  • Each chat has a chat_state.active_session_id. Plain-text dispatches to active session; commands manipulate the set.
  • /session switch reply is 📍 [label] + tail session_switch_preview_lines (default 3) of the transcript stored in sessions.transcript_tail.
  • Inline keyboard quick-pick via ses:switch:<id> callback.

File changes

  • src/bot/{router,notifier,keyboards}.ts, src/bot/commands/index.ts
  • src/session/manager.ts (Mutex, abort handle).

M2 — Claude adapter + streaming

Design decisions

  • query() with options: cwd, canUseTool, hooks, settingSources: ['user','project','local'], permissionMode: 'default', conditional resume.
  • AbortController wired through abortController: { signal } (matches SDK's accepted shape via cast to bypass private constructor surface).
  • Streaming output flows through Notifier.appendStream(key, chunk) with 700ms debounce + token-bucket rate-limit (1 token/s, burst 3) + edit/rotate (50 edits / 3500 chars / 5 min).
  • sdk_session_id captured from every message's session_id field, persisted on first sight.

File changes

  • src/agents/{types,claude,registry}.ts, src/bot/notifier.ts

M3 — canUseTool + Policy + interactive approve

Design decisions

  • PolicyEngine compiles each rule once at load. Form: Tool(arg-glob) or bare Tool. Arg-glob uses custom globToRegex (* → .*). Substitution: {{project_dir}} swapped per call.
  • Decision order: deny first, then allow, else ask.
  • ApprovalBroker in-process Map<requestId, {resolve, timer, request}>. callback_data = apv:once|always|deny:<requestId> — requestId only (plan §10).
  • allow_always tap appends bare tool name to policy.yaml via atomic tmp+rename (broad; user refines by hand).
  • Timeout fallback resolves 'timeout', which adapter coerces to deny + notify.
  • fs.watch on policy.yaml with 150ms debounce → reload.
  • Inline hooks (PreToolUse, Stop) registered through options.hooks for logging only — canUseTool owns permission decisions.

File changes

  • src/approval/{broker,policy}.ts, hook callbacks inline in src/agents/claude.ts

M4 — Kiro adapter via CLI

Design decisions

  • execa(binary, ['chat', '--mode', mode, '--reuse-window', prompt], { cwd, cancelSignal }).
  • Fire-and-notify: emits a single Telegram text "Sent to Kiro IDE" on success.
  • Aborts via cancelSignal from SessionManager.
  • /screenshot uses screencapture -x /tmp/….png then sends as photo.

File changes

  • src/agents/kiro.ts, /screenshot in src/bot/commands/index.ts

M5 — Hardening

Design decisions

  • pino redact paths cover bot token, ANTHROPIC_API_KEY, Authorization, env-leak shapes.
  • Notifier scrub regex catches Telegram tokens (\d+:[A-Za-z0-9_-]{35}), sk-ant-*, OpenAI sk-*, GitHub gh[psoru]_*, Bearer headers — applied before any send/edit.
  • On boot: markRunningAsInterrupted() flips stale sessions and the daemon notifies the original chat_id.
  • Per-session Mutex.isLocked() emits ⏳ busy error event if another dispatch hits an active session.
  • Notifier rotates to a new message after 50 edits, 3500 chars, or 5 min.
  • Policy write: tmp file + fs.renameSync, mode 0600.
  • Tool log pruned hourly beyond 7 days.
  • All SQL via db.prepare(…).run/get/all.

8. Known gaps / deviations

  • Kiro stream-back: out of scope per plan §9 M4 (phase 1 only).
  • Hono: dropped per plan §6 (optional health endpoint).
  • picomatch: replaced by inline globToRegex; rationale in §1.
  • E2E Telegram test: not runnable from agent (needs real bot + chat). Unit suites cover the logical pieces; manual smoke-run via npm start is straightforward once ~/.telecode/.env is present.
  • SDK abort cast: abortController: { signal } uses a structural cast — the SDK accepts a duck-typed object but the type omits this shape. Safe at runtime; flagged for future SDK type alignment.
