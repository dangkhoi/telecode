1. Overview & diff vs plan

v0.4 plan implemented end-to-end. No scope cuts. Deviations:

  • Policy glob matcher uses a hand-rolled globToRegex instead of picomatch: command-style args like rm -rf* need * to span spaces and slashes (picomatch's * is single-segment by default). The custom matcher treats * as .* — closer to plan §8 expected behaviour. picomatch dep removed.
  • Hono left out (plan §6 already marked optional).
  • Kiro adapter is phase-1 fire-and-notify per plan §9 M4.

3. Module-by-module design

M0 — Foundation

Context

Bootstrap, deps pinned, SQLite schema, launchd installer + BotFather wizard.

Requirements

  • Node 22 ESM, TS strict NodeNext.
  • SQLite WAL with tables projects, sessions, tool_log, approvals, chat_state.
  • launchd plist with KeepAlive, RunAtLoad, log path → ~/.telecode/logs/.
  • Workspace scanner depth 1, exclude node_modules/.git/dist/build.

Design decisions

  • Schema kept in src/session/schema.sql; build copies to dist/session/schema.sql so runtime loads via readFileSync. Test path tries dev fallback.
  • Workspace scan now records every directory at any allowed depth (fixes off-by-one vs plan).
  • Env loader is minimal hand-rolled to avoid dotenv dep.

File changes

  • package.json, tsconfig.json, .gitignore, config.example.yaml, policy.example.yaml
  • src/config.ts, src/util/{paths,env,logger,scrub,workspace-scanner}.ts

M1 — Telegram round-trip + SessionManager

Design decisions

  • grammY + @grammyjs/runner. Whitelist middleware drops non-allowed user IDs before any other handler.
  • Each chat has a chat_state.active_session_id. Plain-text dispatches to active session; commands manipulate the set.
  • /session switch reply is 📍 [label] + tail session_switch_preview_lines (default 3) of the transcript stored in sessions.transcript_tail.
  • Inline keyboard quick-pick via ses:switch:<id> callback.

File changes

  • src/bot/{router,notifier,keyboards}.ts, src/bot/commands/index.ts
  • src/session/manager.ts (Mutex, abort handle).

M2 — Claude adapter + streaming

Design decisions

  • query() with options: cwd, canUseTool, hooks, settingSources: ['user','project','local'], permissionMode: 'default', conditional resume.
  • AbortController wired through abortController: { signal } (matches SDK's accepted shape via cast to bypass private constructor surface).
  • Streaming output flows through Notifier.appendStream(key, chunk) with 700ms debounce + token-bucket rate-limit (1 token/s, burst 3) + edit/rotate (50 edits / 3500 chars / 5 min).
  • sdk_session_id captured from every message's session_id field, persisted on first sight.

File changes

  • src/agents/{types,claude,registry}.ts, src/bot/notifier.ts

M3 — canUseTool + Policy + interactive approve

Design decisions

  • PolicyEngine compiles each rule once at load. Form: Tool(arg-glob) or bare Tool. Arg-glob uses custom globToRegex (* → .*). Substitution: {{project_dir}} swapped per call.
  • Decision order: deny first, then allow, else ask.
  • ApprovalBroker in-process Map<requestId, {resolve, timer, request}>. callback_data = apv:once|always|deny:<requestId> — requestId only (plan §10).
  • allow_always tap appends bare tool name to policy.yaml via atomic tmp+rename (broad; user refines by hand).
  • Timeout fallback resolves 'timeout', which adapter coerces to deny + notify.
  • fs.watch on policy.yaml with 150ms debounce → reload.
  • Inline hooks (PreToolUse, Stop) registered through options.hooks for logging only — canUseTool owns permission decisions.

File changes

  • src/approval/{broker,policy}.ts, hook callbacks inline in src/agents/claude.ts

M4 — Kiro adapter via CLI

Design decisions

  • execa(binary, ['chat', '--mode', mode, '--reuse-window', prompt], { cwd, cancelSignal }).
  • Fire-and-notify: emits a single Telegram text "Sent to Kiro IDE" on success.
  • Aborts via cancelSignal from SessionManager.
  • /screenshot uses screencapture -x /tmp/….png then sends as photo.

File changes

  • src/agents/kiro.ts, /screenshot in src/bot/commands/index.ts

M5 — Hardening

Design decisions

  • pino redact paths cover bot token, ANTHROPIC_API_KEY, Authorization, env-leak shapes.
  • Notifier scrub regex catches Telegram tokens (\d+:[A-Za-z0-9_-]{35}), sk-ant-*, OpenAI sk-*, GitHub gh[psoru]_*, Bearer headers — applied before any send/edit.
  • On boot: markRunningAsInterrupted() flips stale sessions and the daemon notifies the original chat_id.
  • Per-session Mutex.isLocked() emits ⏳ busy error event if another dispatch hits an active session.
  • Notifier rotates to a new message after 50 edits, 3500 chars, or 5 min.
  • Policy write: tmp file + fs.renameSync, mode 0600.
  • Tool log pruned hourly beyond 7 days.
  • All SQL via db.prepare(…).run/get/all.

4. SQLite schema

projects(id, name UNIQUE, path, created_at)
sessions(id PK, label, agent, project_id → projects, chat_id,
         sdk_session_id, status, created_at, updated_at,
         last_message, transcript_tail)
  unique(chat_id, label) where status != 'closed'
tool_log(id PK, session_id, tool_name, input_preview, decision, duration_ms, created_at)
approvals(id PK, session_id, tool_name, input_json, decision, created_at, resolved_at)
chat_state(chat_id PK, active_session_id, active_project_id)

WAL mode + synchronous = NORMAL + foreign_keys = ON.

8. Known gaps / deviations

  • Kiro stream-back: out of scope per plan §9 M4 (phase 1 only).
  • Hono: dropped per plan §6 (optional health endpoint).
  • picomatch: replaced by inline globToRegex; rationale in §1.
  • E2E Telegram test: not runnable from agent (needs real bot + chat). Unit suites cover the logical pieces; manual smoke-run via npm start is straightforward once ~/.telecode/.env is present.
  • SDK abort cast: abortController: { signal } uses a structural cast — the SDK accepts a duck-typed object but the type omits this shape. Safe at runtime; flagged for future SDK type alignment.
